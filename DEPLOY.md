# Deploy Devine Adventure (Render + Supabase)

Stack:

| Piece | Host |
|-------|------|
| Web (Next.js) | Render Web Service |
| API (NestJS) | Render Web Service |
| Postgres | **Supabase** (production DB) |

Repo already includes `render.yaml` and Prisma migrations.

---

## 1. Supabase project

1. Create a project at [supabase.com](https://supabase.com).
2. Open **Project Settings → Database**.
3. Copy two connection strings:

### `DATABASE_URL` (pooled — app runtime)

Use **Transaction** pooler (port **6543**), URI mode:

```text
postgresql://postgres.[PROJECT-REF]:[PASSWORD]@aws-0-[REGION].pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=1
```

### `DIRECT_URL` (direct — migrations)

Use **Session** mode or direct host (port **5432**):

```text
postgresql://postgres.[PROJECT-REF]:[PASSWORD]@aws-0-[REGION].pooler.supabase.com:5432/postgres
```

or the classic direct host:

```text
postgresql://postgres:[PASSWORD]@db.[PROJECT-REF].supabase.co:5432/postgres
```

Add `?sslmode=require` if the string does not already enforce SSL.

> Prisma uses `DATABASE_URL` for the running API and `DIRECT_URL` for `prisma migrate deploy`.

## 3. Deploy with Render Blueprint

1. Log in to [dashboard.render.com](https://dashboard.render.com).
2. **New → Blueprint**.
3. Connect the `devine-adventure` GitHub repo, branch `main`.
4. Render reads `render.yaml` and creates:
   - `devine-adventure-api`
   - `devine-adventure-web`
5. For each **sync: false** env var, paste values before apply:

### API service env

| Key | Value |
|-----|--------|
| `DATABASE_URL` | Supabase **pooled** URI (`:6543`, `pgbouncer=true`) |
| `DIRECT_URL` | Supabase **direct** URI (`:5432`) |
| `FRONTEND_URL` | Temporary: `https://devine-adventure-web.onrender.com` (fix after first web deploy if name differs) |
| `APP_URL` | Temporary: `https://devine-adventure-api.onrender.com` |
| JWT secrets | Auto-generated by blueprint (`generateValue`) |
| M-Pesa / Stripe / Mailchimp | Optional; leave empty for first launch |

### Web service env

| Key | Value |
|-----|--------|
| `NEXT_PUBLIC_API_URL` | `https://devine-adventure-api.onrender.com/api/v1` |

> `NEXT_PUBLIC_*` is baked in at **build** time. If the API hostname changes, **Manual Deploy → Clear build cache & deploy** the web service after updating the var.

6. Apply the blueprint and wait for both services to go **Live**.

---

## 4. Wire CORS + public API URL

After both services are live, copy the real URLs from Render:

1. API → **Environment** → set:
   - `FRONTEND_URL` = web URL (e.g. `https://devine-adventure-web.onrender.com`)
   - `APP_URL` = API URL
2. Web → **Environment** → set:
   - `NEXT_PUBLIC_API_URL` = `https://<api-host>/api/v1`
3. Redeploy **web** (so Next picks up the public API URL).
4. Redeploy **api** if you changed `FRONTEND_URL`.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| Migrate fails / prepared statement error | `DATABASE_URL` must be pooler with `pgbouncer=true`; `DIRECT_URL` must be direct `:5432` |
| CORS blocked in browser | `FRONTEND_URL` must exactly match the web origin (https, no trailing slash) |
| Web calls `localhost:3001` in prod | Rebuild web with correct `NEXT_PUBLIC_API_URL` |
| API crash on boot | Check Render logs for Prisma connection / missing JWT secrets |
| Free tier sleep | First request after idle can take ~30s; upgrade plan for always-on |

## Manual service setup (no Blueprint)

If you prefer the UI:

### API

- **Root Directory:** `devine-adventure-api`
- **Build:** `npm ci && npm run build`
- **Start:** `npx prisma migrate deploy && npm run start:prod`
- **Health:** `/api/v1/health`

### Web

- **Root Directory:** `devine-adventure-web`
- **Build:** `npm ci && npm run build`
- **Start:** `npm run start`
- **Env:** `NEXT_PUBLIC_API_URL=https://<api>/api/v1`
